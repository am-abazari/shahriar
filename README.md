# شهریار

**بستری برای انتشار شعر با صدای شاعر، هم‌زمان با متن.**

هر بیت دقیقاً در همان لحظه‌ای که خوانده می‌شود روشن می‌شود.

## چه می‌کند

یک فایل صوتی — دکلمه، غزل‌خوانی یا ترانه — بارگذاری می‌کنید، متن شعر را
می‌چسبانید، و برای هر مصرع می‌گویید از چه ثانیه‌ای تا چه ثانیه‌ای خوانده می‌شود.
شنونده متن را می‌بیند و هر مصرع همان‌طور که شنیده می‌شود روشن می‌شود.

**مرزها هرگز روی هم نمی‌افتند.** وقتی زمان پایان یک مصرع را ثبت می‌کنید، همان عدد
به‌عنوان زمان شروع مصرع بعدی می‌نشیند. مرز مشترک دو مصرع *یک عدد* است، نه دو عدد
مستقل؛ به همین دلیل تداخل در این مدل اصلاً قابل بیان نیست. ورود دستی هم به همین
قاعده پایبند است: نمی‌توانید شروع یک سطر را به داخل سطر پیشین ببرید.

قالب‌های پشتیبانی‌شده: غزل، مثنوی، رباعی و دوبیتی، شعر نو، و ترانه.

## راه‌اندازی

```bash
npm install
npm run dev
```

بدون هیچ پیکربندی بالا می‌آید: اگر `DATABASE_URL` تنظیم نشده باشد، یک پستگرسِ
درون‌فرایندی در `.data/pg` ساخته می‌شود. برای ورود به بخش مدیریت، در `.env.local`
یک `ADMIN_PASSWORD` بگذارید.

| متغیر | نقش |
| --- | --- |
| `DATABASE_URL` | نشانی پستگرس. روی ورسل با افزودن Neon خودکار تنظیم می‌شود. |
| `ADMIN_USERNAME` | نام کاربری نخستین ورود (پیش‌فرض: `admin`). |
| `ADMIN_PASSWORD` | رمز نخستین ورود. پس از ورود از خودِ برنامه قابل تغییر است. |
| `AUTH_SECRET` | کلید امضای نشست و رمزگذاری اعتبارنامه. یک رشته‌ی تصادفی بلند. |

## استقرار روی ورسل

۱. مخزن را به ورسل وصل کنید (فریم‌ورک به‌صورت خودکار Next.js شناسایی می‌شود).
۲. از بخش Storage یک دیتابیس Neon بسازید و به پروژه وصلش کنید؛ `DATABASE_URL`
   خودکار تزریق می‌شود.
۳. `ADMIN_PASSWORD` و `AUTH_SECRET` را در Environment Variables بگذارید.

## معماری

```
مرورگر ─────► Next.js (App Router)          صفحه‌ها، رندر سمت سرور
               │
               └─► /api/*  ─► Express ─────► PostgreSQL
                              (تابع بدون‌سرور)
```

سرور Express به‌صورت یک تابع بدون‌سرور در `src/pages/api/[[...path]].ts` اجرا
می‌شود؛ همان نمونه در فراخوانی‌های بعدی بازاستفاده می‌شود.

**صوت هم در همان پستگرس می‌ماند.** فایل به ردیف‌های ۵۱۲ کیلوبایتی شکسته می‌شود و
پاسخ به هر درخواست `Range` فقط ردیف‌های هم‌پوشان را می‌خواند، نه کل فایل را؛ پس
جابه‌جایی روی نوار پخش ارزان است و حافظه‌ی تابع ثابت می‌ماند. چون سقف بدنه‌ی
درخواست در توابع بدون‌سرور حدود ۴٫۵ مگابایت است، آپلود در مرورگر به بخش‌های ۳
مگابایتی بریده می‌شود؛ بخش‌ها روی ردیف‌های هم‌تراز می‌نشینند، پس ارسال دوباره‌ی یک
بخشِ ناموفق فقط همان ردیف‌ها را بازنویسی می‌کند.

```
src/
├─ app/                صفحه‌ها (App Router)
├─ components/         ویرایشگر هم‌زمان‌سازی، پخش‌کننده، صحنه‌ی نمایش لیریکس
├─ lib/                مدل داده، موتور زمان‌بندی، ابزار زمان — مشترک میان کلاینت و سرور
├─ pages/api/          ورودی تابع بدون‌سرور که Express را اجرا می‌کند
└─ server/
   ├─ db/              پستگرس: قطعه‌ها، صوت، تنظیمات
   ├─ routes/          مسیرهای Express
   └─ auth.ts          اعتبارنامه و نشست
```

## دسترسی

انتشار و ویرایش فقط برای ادمین است؛ شنیدن برای همه آزاد. رمز با `scrypt` درهم
می‌شود و اعتبارنامه پیش از رسیدن به دیتابیس با `aes-256-gcm` مهر می‌شود، پس یک
نسخه‌ی لو رفته از دیتابیس بدون کلید سرور چیزی به دست نمی‌دهد.

## میان‌برهای صفحه‌کلید

**هنگام شنیدن** — `فاصله` پخش/مکث · `↑` `↓` بیت پیشین و بعدی ·
`←` `→` پنج ثانیه جلو و عقب · `R` تکرار بیت · `M` بی‌صدا

**هنگام زمان‌بندی** — `S` ثبت شروع سطر · `Enter` ثبت پایان و رفتن به سطر بعدی
